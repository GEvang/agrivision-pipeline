# Open Data Documentation Template

## 1. Dataset Identification

Dataset Title: AgriVision Pipeline Run Artifacts and Export Package Data

Short Description: Data products generated by AgriVision Pipeline from drone imagery and optional OpenAgri service enrichment, including uploaded image manifests, run status/parameter records, vegetation-index rasters, grid summaries, weather/irrigation/PDM enrichment outputs, HTML reports, and ZIP export packages with JSON-LD metadata.

## 2. Purpose and Context

The data artifacts support agricultural drone-imagery analysis and OpenAgri-style interchange. AgriVision Pipeline generates local operator artifacts from uploaded or pre-staged imagery, OpenDroneMap orthophotos, vegetation-index analysis, grid classification, optional weather/irrigation/PDM enrichment, and report generation.

Intended users include AgriVision operators, agronomists, downstream analytics systems, and OpenAgri-style consumers that use exported run packages and metadata.

Funding source: `This project has received funding from the European Union's Horizon Europe research and innovation programme under grant agreement No 101134083.`

## 3. Temporal and Spatial Coverage

Temporal Coverage (start-end): No fixed dataset-wide temporal coverage is documented. Individual runs include `created_at`, `updated_at`, `started_at`, and `finished_at` fields, and run parameters may include `flight_date` when supplied.

Spatial Coverage (region, coordinates): Any farmer can upload a dataset for analysis. The application has currently been tested in Greece, especially Crete. Default configuration uses `Neapolis, Agios Nikolaos, Crete` with latitude `35.2600` and longitude `25.6000`. Actual run/dataset coverage depends on uploaded imagery and operator configuration and should be documented per exported dataset.

## 4. Data Collection Methodology

Data sources:

- Operator-uploaded RGB, MAPIR, and/or thermal drone imagery.
- Imported ready orthophotos where used.
- OpenDroneMap-generated orthophotos.
- Computed vegetation-index and grid outputs.
- Optional OpenAgri Weather Service, Irrigation Management Service, and Pest & Disease Management Service outputs.
- Dashboard/CLI run metadata and logs.

Sampling method: Farmer/operator-supplied geotagged imagery per uploaded parcel or dataset. The repository does not document a formal field sampling plan or flight protocol.

Measurement frequency: On demand per uploaded dataset or pipeline run. External weather/irrigation data frequency depends on configured services.

Instruments used: To be confirmed. The code supports RGB, MAPIR/multispectral, and thermal imagery, but no specific drone/camera model is documented as the official dataset instrument.

Calibration procedures: No formal field or camera calibration procedure is documented. Camera calibration is not required from farmers for the documented processed-output workflow unless OpenAgri requires instrument-level dataset metadata.

Quality control:

- Upload validation checks file type, duplicate names, empty files, and unreadable/corrupt images.
- Pydantic schemas validate run creation, run status, settings, credentials, and report view structures.
- Export packages include manifests and JSON-LD metadata.
- Tests cover grid classification/rendering, disease-risk scoring, export service, dashboard APIs/services, config modules, and failure diagnostics.

## 5. Data Structure and Format

File formats:

- JPEG/JPG and other accepted image files for uploads, based on dashboard upload validation.
- GeoTIFF (`.tif`, `.tiff`) for vegetation-index rasters and orthophotos.
- PNG for previews, overlays, and report assets.
- CSV for grid and disease-risk cell/category outputs.
- JSON for run status, parameters, outputs, manifests, weather, irrigation, PDM, and quality metadata.
- JSON-LD for OpenAgri-oriented run metadata and selected weather artifacts.
- HTML for reports.
- ZIP for run export packages.
- Plain text for run logs.

Encoding:

- JSON files are written as UTF-8 by repository helpers.
- CSV encoding is not explicitly documented.
- HTML encoding is not explicitly documented.

Folder structure:

```text
data/uploads/<upload_id>/          Uploaded image datasets and upload manifests
runtime/runs/<run_id>/             Run records, params, status, outputs, logs, previews
runtime/exports/                   ZIP export packages
output/ndvi/                       Vegetation-index rasters, overlays, grid CSV/metadata
output/ndvi/disease_risk/          Disease-risk overlays, cells, summary
output/weather/                    Weather enrichment JSON/JSON-LD artifacts
output/irrigation/                 Irrigation enrichment artifacts
output/pdm/                        Pest & Disease enrichment artifacts
output/runs/<run_id>/              Per-run reports and orthophotos
output/report_assets/              Report asset images
```

Run export package structure:

```text
manifest.json
metadata/run_metadata.jsonld
run/status.json
run/params.json
run/outputs.json
run/run.log
report/report.html
rasters/vegetation_index.tif
rasters/orthophoto_rgb.tif
rasters/orthophoto_mapir.tif
rasters/orthophoto_thermal.tif
quality/vegetation_index.png
quality/grid_overlay.png
quality/grid_cells.csv
quality/grid_categories.csv
quality/metadata.json
quality/grid_metadata.json
risk/disease_risk_summary.json
risk/*_overlay.png
risk/*_cells.csv
```

Files are included when present for a given run.

## 10. Privacy, Ethics, and GDPR Compliance

Does the dataset contain personal data? Processed public outputs are intended to exclude raw drone imagery. Uploaded geotagged images may contain location information; no other personal data is expected from the current workflow.

Anonymization methods: Raw uploaded imagery is not intended for public distribution; processed-output publication is planned. No additional anonymization workflow is documented.

Legal basis for processing: To be confirmed.

Ethical considerations:

- Operators should avoid uploading or publishing imagery that contains identifiable people, private property details beyond project scope, or sensitive locations unless appropriate legal basis and permissions exist.
- Real credentials and tokens must not be included in shared artifacts.

## 11. Access and Distribution

Download links:

- Farmers upload datasets and download processed parcel analysis through the AgriVision dashboard.
- Public farmer-facing data/export discovery or distribution is planned through the OpenAgri Portal.
- Public outputs should include processed outputs only, not raw drone imagery.
